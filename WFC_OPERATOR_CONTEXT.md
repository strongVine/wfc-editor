# Контекст: WFC `rotationMap` как оператор

Адресовано ЛЛМ. Базовое (что такое WFC, propagation в общем смысле, битовые операции) опускаю — ты это знаешь. Документ объясняет **специфику этой реализации**: соглашения о поворотах, упаковку, семантику строк матрицы, формулу симметрии с её выводом, и места, где легко соскользнуть.

## 0. Глоссарий

Строгие определения. При противоречии между телом документа и глоссарием — главный глоссарий.

```
Клетка       — позиция в сетке (Vector3Int). Контейнер. Сама ничего
               не хранит, кроме ссылки на тайл (Map.dictionary).

Тайл         — объект в клетке. Один на клетку. Сущность ECS
               (компонент Tile<TContext>). Хранит суперпозицию
               и схлопывается до одной конфигурации.

Состояние    — индекс 0..15. Тип конфигурации без учёта поворота.
               В коде: selfStateIndex, индекс nibble в ulong directs,
               индекс строки в rotationMap[state, direction].

Поворот      — индекс 0..3. r=0 Front (база), r=1 Right (90° CW),
               r=2 Back, r=3 Left. Действие на тайл, не на мир:
               «тайл в повороте r» = его локальный Front смотрит
               в мировое направление r.

Конфигурация — пара (состояние, поворот). Один бит в ulong directs
               на позиции state*4 + rotation. Это «атом» оператора.

Суперпозиция — множество живых конфигураций тайла. Хранится в
               ulong directs (64 бита = 16 состояний × 4 поворота).
               Тайл с >1 живым битом — в суперпозиции.

Схлопнутый   — тайл с ровно 1 живым битом. Конфигурация определена.
тайл           Тайл с 0 битами — противоречие, ошибка генерации.
```

В §7 переменные `A`, `B` — это **состояния** (индексы 0..15). `(A, 0)`, `(B, r)` — конфигурации. Если в рассуждении начинаешь называть `A` тайлом — это ошибка.

## 1. Рамка

Это **коллапс волновой функции в буквальном математическом смысле**. Не аналогия. Структура изоморфна квантовой:

- Тайл хранит суперпозицию конфигураций.
- Матрица играет роль оператора: применяясь к суперпозиции одного тайла в направлении соседа, даёт суперпозицию допустимых конфигураций соседа.
- Сосед коллапсирует: его старая суперпозиция пересекается с пришедшим ограничением.
- Если суперпозиция соседа изменилась, он сам теперь — источник; волна катится дальше.

«Оператор» здесь — не линейный оператор и не матрица собственных значений. Это просто функция типа «суперпозиция → суперпозиция»; на чистом состоянии задана таблично (см. §4), на смешанном вычисляется объединением (см. §5).

**Антисловарь — про природу оператора.** Если в рассуждении про физику/онтологию матрицы всплывают слова **«правило», «разрешено», «запрещено», «программист обязан соблюдать симметрию», «валидатор правильности заполнения»** — стоп, переформулируй. Это рамка из теории констрейнтов, и из неё нельзя нормально думать про этот код. Рабочие термины: *суперпозиция, конфигурация, оператор, применить, схлопнуть, распространить, противоречие, профиль стороны*.

Симметрия в этой рамке — **не правило, которое надо соблюдать**, а необходимое условие, без которого матрица не является оператором. См. §7.

**Уровень инструмента — другой словарь.** Когда речь идёт о редакторе матриц или похожем тулзинге, который технически дописывает зеркальный бит при каждом действии пользователя — слова «дополнение», «зеркало», «синхронизация» уместны. Они описывают механику инструмента, не природу оператора. Антисловарь сюда не распространяется.

## 2. Упаковка суперпозиции тайла

```
ulong directs   // суперпозиция одного тайла
                // 64 бита = 16 состояний × 4 поворота
                // бит на позиции (state*4 + rotation)
                // = "конфигурация (state, rotation) существует здесь как возможность"
```

- **>1 бит** → тайл ещё в суперпозиции.
- **1 бит** → схлопнут, конфигурация определена.
- **0 бит** → противоречие. Это рантайм-ошибка генерации.

Почему биты, а не структуры/списки: пересечение и объединение конфигураций — это одна машинная инструкция (`&`, `|`). Вся производительность propagation на этом стоит. Не предлагать переписать через `List<Configuration>` — это убьёт горячий путь.

Потолок 16 состояний — это потолок упаковки в `ulong` (16 nibble'ов по 4 бита). Не настройка, а арифметика.

## 3. Соглашение о повороте

Поворот — на 90° вокруг вертикальной оси. Группа C₄, четыре значения.

Биты внутри nibble нумеруются:
```
бит 0 — Front   (rotation = 0, базовый, без поворота)
бит 1 — Right   (поворот на 90° по часовой)
бит 2 — Back    (180°)
бит 3 — Left    (270°)
```

**Что значит «тайл в повороте r»**: его локальная сторона Front смотрит в мировое направление r. Поворот — действие на тайл, не на мир.

Ротация nibble (см. `RotateMask` в `BinaryExtensions`) = циклический сдвиг битов внутри nibble влево на r позиций. Соответствует тому, что если у тайла была допустима соседняя конфигурация в направлении Front, после поворота на 1 (Right) эта же физическая совместимость теперь относится к мировому направлению Right.

## 4. Матрица оператора

```csharp
ulong[,] rotationMap   // [state, direction] → ulong
                       // state: 0..15      — состояние центрального тайла
                       // direction: 0..5   — направление к соседу (Front, Right, Back, Left, Up, Down)
```

`M[A, d]` — результат применения оператора к **чистой** конфигурации `(A, rotation=0)` в направлении `d`. Формат — та же упаковка, что у `directs` тайла: 16 nibble'ов, **позиция nibble = состояние соседа B**, **биты в нибле = повороты B (в мировой системе) которые могут стоять на этой позиции рядом с A**.

Матрица хранится **только для базового поворота A** (rotation=0). Для других поворотов A не дублируется — пересчёт делается в рантайме (см. §5).

**Семантика одной строки `M[A, d]`** — физический профиль одной стороны базово-ориентированного тайла A: «если я A в повороте 0, то с d-стороны меня могут стоять следующие (state, rotation) пары соседа». Не «правила соседства» абстрактно — буквально форма стороны, упакованная в `ulong`.

## 5. Применение оператора в рантайме

Когда у тайла уже не чистая конфигурация (несколько живых битов), требование к соседу в направлении `d` собирается из всех живых конфигураций:

```csharp
// упрощённо, оригинал — BinaryExtensions.GetMasks
ulong mask = 0;
for каждого состояния A в directs:
    for каждого живого поворота r у A:
        ulong row = M[A, d_local];          // (a) выбор строки матрицы
        ulong rotated = RotateMask(row, r); // (b) пересчёт ниблов соседа
        mask |= rotated;                    // объединение по моим конфигурациям
```

**Двойной пересчёт** — место где имена в коде сбивают. В `GetMasks`:
- `selfStateIndex` — состояние A центрального тайла.
- `selfDirect` — это **поворот** центрального тайла (бит rotation), не направление. Имя обманывает.
- `worldDirect` — мировое направление к соседу.
- `relativeSelfDirect = (worldDirect - selfDirect + 4) % 4` для горизонтали — это локальное направление **в системе тайла A**.

Что происходит:

(a) **Выбор строки**: я повёрнут на r, сосед в мировом направлении d мне локально находится в направлении `(d - r) mod 4`. Беру строку матрицы для этого локального направления — потому что матрица знает только базовую ориентацию.

(b) **Ротация ниблов**: строка матрицы хранит повороты соседа относительно базовой ориентации меня. Меня самого мир видит повёрнутым на r → все ориентации соседа в мировой системе тоже сдвинуты на r → битовая ротация каждого nibble на r позиций.

Объединение `|=` — потому что я ещё не выбрал, в какую конфигурацию схлопнусь. Сосед обязан быть совместим с **любой** из моих живых конфигураций. Множество допустимых соседей = объединение по моим конфигурациям.

## 6. Эталонный пример: House + Grass

Минимальный самодостаточный случай. Два состояния: `c0 House` (с фасадом и тремя стенами без окон), `c1 Grass` (симметричный газон). Желаемый паттерн — чередование полос: ряд домов фасадом к газону, за ними ряд домов спина-к-спине, дальше снова газон, и т.д.

```csharp
//c0 House
{
    //                House    Grass
    /*Front*/ _(0b0000, 0b1111),  // перед домом — Grass любой ориентации
    /*Right*/ _(0b0001, 0b0000),  // справа — House(rot=0), смотрит туда же куда я
    /*Back */ _(0b0100, 0b0000),  // сзади — House(rot=2), спина-к-спине со мной
    /*Left */ _(0b0001, 0b0000),  // слева — House(rot=0)
},
//c1 Grass
{
    //                House    Grass
    /*Front*/ _(0b0100, 0b1111),  // House(rot=2) фасадом ко мне + Grass любой
    /*Right*/ _(0b1000, 0b1111),  // House(rot=3) фасадом ко мне
    /*Back */ _(0b0001, 0b1111),  // House(rot=0)
    /*Left */ _(0b0010, 0b1111),  // House(rot=1)
},
```

Прогон волны от схлопнутого House(rot=0):
- Front: ставится Grass.
- Right, Left: продолжается ряд House(rot=0).
- Back: ставится House(rot=2). Тот сам требует со своего Front (= мировой Back) Grass.

Получается стабильный паттерн: `... | Grass | House→ House→ House→ | ←House ←House ←House | Grass | →House →House ...`. Корректный оператор.

## 7. Симметрия как закон оператора

### Утверждение

Каждый бит в `M[A, d]` — это утверждение о существовании **одной физической пары**: «A в базовом повороте, B в повороте r, по оси d, общая грань». Та же пара, увиденная **со стороны B**, должна быть записана в матрице **тоже** — это то же физическое утверждение, только в другой системе отсчёта.

Если оператор утверждает пару с одной стороны и не утверждает с другой — он внутренне противоречив. Волна, идущая от A к B, говорит «можно», волна от B к A — «нельзя». В произвольной точке мира они столкнутся, и `directs` обнулится.

Это **не правило заполнения, которое программист обязан соблюдать**. Это **необходимое условие, чтобы матрица была оператором вообще**. Асимметричная матрица — не «оператор с ошибкой», она просто не оператор.

### Формула (горизонтальные направления)

Направления горизонтальные: `0=Front, 1=Right, 2=Back, 3=Left`. `opposite(d) = (d + 2) % 4`.

```
если M[A, d] содержит B с битом r,
то   M[B, d'] обязан содержать A с битом r0,
где  d' = (opposite(d) - r + 4) % 4
     r0 = (4 - r) % 4
```

### Формула (вертикальная ось)

Направления `4=Up, 5=Down`. Вокруг вертикальной оси меняется только сторона (Up↔Down) — поворот тайла на 90° вокруг этой же оси не переводит его верх в низ. C₄-поворот при этом сохраняется, поэтому ниблы пересчитываются как в горизонтальном случае:

```
если M[A, d∈{Up,Down}] содержит B с битом r,
то   M[B, d'] обязан содержать A с битом r0,
где  d' = противоположное (Up↔Down)
     r0 = (4 − r) % 4
```

Сторона у вертикали вырождена, ротация ниблов — нет: если бы B стоял со стороны A в мировом повороте r, то A с точки зрения B имеет относительный поворот `(0 − r) mod 4` — ровно как в горизонтальном случае.

Когда вертикаль непустая (например, двух-слойные сцены, где соседи по вертикали — реальные тайлы), формула применима один в один.

### Вывод формулы (горизонтальная геометрия)

Пара зафиксирована: A в базе (rot=0) в клетке X; B в повороте r в клетке Y; ось от X к Y — мировое направление d.

Что видит B в своей системе отсчёта:
1. **Направление**: A для B находится в мировом направлении `opposite(d)` (тривиально). Но матрица B хранится для базового поворота B; B сам повёрнут на r, значит локальная система B провёрнута относительно мировой на r. Чтобы получить локальное направление в системе B, вычитаем r: `d' = (opposite(d) - r) mod 4`.
2. **Поворот A в системе B**: A в мире имеет поворот 0; B в мире — r. Относительный поворот A с точки зрения B — это `0 - r mod 4 = (4 - r) mod 4`. Это и есть `r0`.

### Прогоны на House+Grass

`M[House, Front, Grass] = 0b1111`. Бит `r=2`:
- `d' = (2 - 2 + 4) % 4 = 0` → Front
- `r0 = (4 - 2) % 4 = 2`
- Должно: `M[Grass, Front, House]` содержит бит 2 → `0b0100`. ✓

`M[House, Right, House] = 0b0001`. Бит `r=0`:
- `d' = (3 - 0) % 4 = 3` → Left
- `r0 = 0`
- Должно: `M[House, Left, House]` содержит бит 0 → `0b0001`. ✓

`M[House, Back, House] = 0b0100`. Бит `r=2`:
- `d' = (0 - 2 + 4) % 4 = 2` → Back
- `r0 = 2`
- Должно: `M[House, Back, House]` содержит бит 2 → `0b0100`. ✓ (само на себя — пара House↔House спина-к-спине самосимметрична)

`M[Grass, Right, House] = 0b1000`. Бит `r=3`:
- `d' = (3 - 3 + 4) % 4 = 0` → Front
- `r0 = (4 - 3) % 4 = 1`
- Должно: `M[House, Front, Grass]` содержит бит 1 → `0b1111` содержит → ✓

### Два режима работы с симметрией

Различай.

**Режим A — диагностика существующей матрицы.** Кто-то написал матрицу руками, она уже лежит в коде, и в ней нашлась асимметрия. Из двух противоречащих утверждений неизвестно, какое выражает истинную физику: то ли надо дописать недостающий бит, то ли стереть лишний. Это противоречие в утверждениях оператора, и решает его пользователь — он один знает физический смысл каждой конфигурации. ЛЛМ должна сформулировать какая пара утверждений противоречит, и спросить.

**Режим B — синхронный ввод.** Используется инструмент (`wfc-editor`), который при каждом действии пользователя атомарно ставит/снимает оба зеркальных бита по формуле — как в горизонтальной матрице, так и между двумя матрицами по вертикальной оси. Здесь асимметрии не возникают по построению — нечего диагностировать, нечего автоисправлять. «Дополнение симметрией» в этом режиме — корректное название механики инструмента, не «автоисправление».

Запрет «не автодополнять» относится к режиму A. К режиму B — не относится.

## 8. Распространение волны

Два места с разной алгеброй — не путать.

**`GetMasks`** (см. §5) — собирает требования от моей суперпозиции к гипотетическому соседу:

```
mask = OR по всем моим живым конфигурациям ( их требования к соседу )
```

`|=` потому что любая моя живая конфигурация — кандидат на финальный коллапс. Сосед обязан быть совместим с любой.

**`Tile.Collapse(mask)`** — применяет это требование к существующему соседу:

```
new_directs = side.directs & mask
```

`&` потому что у соседа уже есть его собственное множество живых конфигураций; моё ограничение его **сужает**, а не задаёт заново. Остаётся пересечение.

Дальше:
- `new_directs == old_directs` → ничего нового, волна затухла на этом тайле.
- `new_directs == 0` → противоречие, генерация сломалась.
- иначе → у соседа меньше живых конфигураций; он сам теперь источник, волна катится.

Каскад этих событий и есть распространение коллапса. Если пользователь упомянет «эффект бабочки» — он имеет в виду именно цепной коллапс через волну, не отдельный механизм.

## 9. Антипаттерны

**`0b0000` ≠ «пусто»**. Это «эту конфигурацию здесь поставить нельзя». Если **все** ниблы в строке `M[A, d]` нулевые, то с d-стороны тайла A не может стоять вообще ничего → волна туда упрётся → `directs == 0` у соседа → ошибка генерации.

Уточнение: один нибл `0b0000` = «ни один из 4 поворотов состояния B недопустим в этом направлении рядом с A». Целая нулевая строка `M[A, d]` = «рядом с A в направлении d не может стоять никакое состояние ни в каком повороте» = тайл-сосед получит пустую суперпозицию = ошибка.

Из этого: **«глухой стороны» в этой системе нет**. У каждой стороны каждого активного тайла должны быть допустимые соседи. Если по физике сторона «глухая» (стена дома) — это значит «здесь может стоять только другой такой же глухой сосед», но не «здесь не может ничего».

**Чего нет в списке состояний — того нет в матрице.** Если в рассуждениях возникает «улица», «забор», «крыша» — спросить у пользователя, какому индексу состояния это соответствует. Если такого состояния нет среди объявленных — оперировать им нельзя; надо переформулировать через имеющиеся состояния или попросить добавить новое.

## 10. Что в коде есть, но к формализму оператора не относится

Существует, упоминать только если пользователь спросит явно:

- `RandomRotation` / `RemoveRotation` в `TileExt.Collapse` — постобработка после `&` для отдельных realm'ов.
- `сompletenessMask` в `Realm` — оптимизация: не материализовать соседа, ограничение на которого тривиально.
- `Tile.Empty` / `EmptySide` / `Run_TileOnEmptySide` — механика создания нового тайла в ранее пустой клетке. К алгебре оператора не относится; описывается отдельно если нужно.

К симметрии оператора и пониманию волны это отношения не имеет. Не углубляться.

- При найденной асимметрии в режиме A (см. §7) — не «дописать», а сформулировать какие два утверждения противоречат, и спросить, какое соответствует физике.
- Не использовать антисловарь из §1 при обсуждении физики оператора. На уровне инструмента — словарь свободный.
- Если что-то неясно — задать прямой вопрос. Не додумывать.
